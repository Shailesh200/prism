<Tab value="CLI">

Real exit codes and clean JSON — what makes `prism` useful in a script. Full
command list: [CLI reference](/docs/reference/cli-commands).

## Global options

| Option | Effect |
|---|---|
| `-w, --workspace <path>` | Which repository to analyse |
| `--json` | Emit JSON on stdout instead of a human table |
| `--no-color` | Disable ANSI colour (`NO_COLOR` honoured too) |
| `-q, --quiet` | Suppress progress on stderr |
| `--verbose` | Workspace chosen + index timing on stderr |
| `-y, --yes` | Consent to an operation that would otherwise be refused |
| `--max-file-bytes <n>` | Skip hashing files larger than this |
| `--exclude <glob>` | Extra ignore glob; repeatable |
| `-V, --version` | Engine version and API level |

No subcommand prints help and exits **0**. A near-miss typo exits **2** with a
suggestion.

## Which repository?

Most explicit wins: `--workspace` → `PRISM_WORKSPACE` → nearest `.git` ancestor
→ cwd. `prism doctor` prints which rule won. Path arguments resolve from
**your** directory; paths outside the workspace are refused, not clamped.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Ran successfully |
| `1` | Ran successfully, and found what you gated on |
| `2` | Usage error, or the file, symbol or path you named is not in the index |
| `3` | Prism itself failed |

## Failing a build

```bash
prism blast src/core/index.ts --fail-on high
prism review --base origin/main --fail-on high
prism cycles --fail-on any
```

`--fail-on` takes a [band](/docs/concepts/risk-bands) and fires at or above it.

## Scripting

```bash
prism overview --json | jq '.data.dna.rankedDomains'
```

Success and failure share one JSON wrapper; in `--json` mode errors go to
**stdout** inside it. Colour is never emitted when stdout is not a TTY.
`--json` is never truncated — `--limit` bounds only the human table.

## Worth knowing

- The first command in a repo is slow (it builds the index); later commands
  reuse it.
- `prism review` with no args reviews the working tree, including untracked
  files. Pass `--base` in CI.
- `prism rename` and `prism safe-delete` never write — they only report.

<Tab value="AI agents (MCP)">

You set Prism up once. After that, ask for what you want — the server's
instructions teach the agent which tools to call, so you never type a tool name.
Prism does not make the edit. Your agent does, in your chat.

## Default tools

The server registers every tool, including `receipt`. The ones the instructions teach first:

| Tool | For |
|---|---|
| `prepare_change` | Before an edit: files to open, helpers to reuse, House Style, no file bodies |
| `blast_radius` | What depends on a file or symbol, and how risky a change is |
| `guard_session` | Which dirty files to read first |
| `test_impact` | Which tests cover a change |
| `habits` | Your saved routines (e.g. "start my day") as steps your agent runs with its own tools |
| `safe_delete` | Whether a file or symbol can go, with blockers and orphans |
| `rename_impact` | Every reference a rename has to touch |
| `repository_overview` | What this repository is and where to start |
| `graph` | Find a symbol or path, its neighbours, how A reaches B, what an area is for |

The rest, including `receipt`, are on too. Each is listed in the [MCP reference](/docs/reference/mcp-tools).

## How to talk

| You say | Agent should use |
|---|---|
| "What is this repo?" / "Orient me" | `repository_overview` |
| "Where does checkout live?" | `graph` (find, then explain) |
| "I'm about to add caching to fetchUser" | `prepare_change` first — pack, reuse, House Style, no bodies |
| "I'm about to edit `src/…` — what breaks?" | `blast_radius`, `test_impact` |
| "What should I read first in this dirty tree?" | `guard_session` |
| "Review my current changes" | `guard_session`, then `blast_radius` on what it flags |

With the Prism plugin pack installed, the stop hook runs the checks the
change reaches when the agent stops, and prints a receipt with a verdict:
SHIP, NOT PROVEN or NO-SHIP.

Optional [prompts](/docs/reference/mcp-prompts) appear in clients that show a
prompt picker.

## How the server behaves

1. Handshake is fast — connecting does not index.
2. The first tool call may take seconds while the index builds.
3. stdio only — diagnostics on stderr and logging notifications.
4. Lists are bounded (`totalCount` / `truncated`). A cut list says so.
5. Paths outside the workspace are refused.
6. No tool edits your repository, makes a network call, or holds third-party
   credentials — see [privacy](/privacy).

## Force a specific repo path

Only if auto-detection is wrong:

```bash
prism-mcp --workspace ~/code/my-app
# or
PRISM_WORKSPACE=~/code/my-app prism-mcp
```

Put the same into the client's `args` / `env` if needed.

## If something fails

1. Run `prism doctor` inside the same project.
2. Check the workspace (MCP roots / git root vs cwd). If a tool reports the
   wrong repository, reload prism with the git project open.
3. Run `prism doctor --surfaces` to see which Node each client launches.
4. Disable and re-enable **prism** in the client, or restart it.
5. Set `PRISM_WORKSPACE` once and retry.

All tools: [MCP reference](/docs/reference/mcp-tools).
