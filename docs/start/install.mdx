Prism 2.0 is one CLI and one MCP server (`prism-mcp`) that ship together. You do
**not** need to clone the Prism repo. Prefer a short path? Use the
[install wizard](/install).

## 1. Prerequisites

<Steps>
<Step>

**Node.js** — check with `node -v`.

</Step>
<Step>

**A project folder.** Git is recommended (the stop receipt and test impact
read it) but not required.

</Step>
</Steps>

## 2. Install and wire your agent

```bash
npm install -g @repo-prism/cli
prism install claude     # or: cursor, codex, opencode, all
```

`prism install` writes the MCP entry, the hooks or the rule line for each host,
and records what it wrote in `~/.prism/install.json`, so `prism uninstall`
removes exactly that and nothing else. It does not ask (running it is the
go-ahead), but it backs up each config to `~/.prism-backups/<time in UTC>/`
first, then prints what it wrote and where the backups are. Claude Code gets
a verdict when the agent stops; Codex and opencode get it with the next
receipt. In Cursor, Prism gives a receipt when the agent asks for one. The
automatic verdict when the agent stops isn't available in Cursor yet. The MCP entry launches the installed
`prism-mcp` binary — never a registry download.

Wiring a host by hand? Use `npx -y @repo-prism/mcp-server@2` as the server
command; each agent’s [install page](/install) has the snippet.

## 3. Confirm it works

```bash
prism doctor
```

`prism doctor` checks each host it wired, the binary the hooks will run, and
the index for the current repository. In your agent, ask "what breaks if I
change this file?" — it answers from Prism's graph.

Something off? [Troubleshooting](/docs/help/troubleshooting).

## Upgrade

```bash
npm install -g @repo-prism/cli
prism upgrade            # optional: re-link every agent now
```

`prism upgrade` lists the files it would change and asks y/N, then backs
them up and re-links your agents. Scripts and `--json` need `--yes`.

Releases sometimes change the hooks Prism registers (2.0 adds a background
Stop hook that reports the verdict when the checks finish). Prism never
changes your agent configs on its own. When a Claude Code session starts with
Prism hooks from an earlier release, it prints one line, at most once a day:
run `prism doctor --fix`. That lists the files it would change and asks
before it writes. On yes it backs up each file to
`~/.prism-backups/<time in UTC>/`, then updates Prism's own entries and keeps
your other hooks. The new hooks apply from the next session. In a script, use
`prism doctor --fix --yes`; `prism doctor --fix --dry-run` only shows the list.

If Prism's entries were edited by hand, or run from two places, the line
names `prism install claude` instead (`prism install claude --project` for a
repository's settings). `prism doctor` shows the same check. Set
`PRISM_HOOK_REFRESH=0` to turn the check off.

opencode runs the new hook through its existing plugin file, so it needs
nothing. Cursor and Codex have no Prism hooks to update.

## What Prism writes

Nothing goes into your checkout. State lives in the machine-wide library:

```
~/.prism/
  install.json            what prism install wrote, for prism uninstall
  config.json             optional: extraTools[] (opt-in MCP tools)
  events.jsonl            what hooks, the daemon and the snapshot writer did
  update.json             the daily update check (never relaunches)
  workspaces/<key>/
    cache/                the index
    hooks/snapshot.json   what hooks read (under their latency budget)
    receipts/             the last 20 stop receipts
    memory.json           notes saved with prism remember
```

`prism data prune` lists empty workspace folders, caches of deleted checkouts,
and untracked worktrees; `prism data prune --yes` removes them.
